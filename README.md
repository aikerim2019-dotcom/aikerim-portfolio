# Айкерим Кусанова — кәсіби портфолио

## Сайттың ішіндегі басқару

Енді әр файлды қосу немесе жою үшін GitHub бетіне өту қажет емес. «Басқаруға кіру» арқылы осы ашық бетте басқаруды қосыңыз. Құжаттар мен фотоларды сайттағы файл таңдау терезесінен бірнешеуден қосуға болады. «Жою» → «Иә, жою» тек таңдалған файлды серверден жояды және сайттағы тізімді бірден жаңартады.

## Бастапқы баптау

GitHub-та fine-grained personal access token жасаңыз: тек aikerim2019-dotcom/aikerim-portfolio репозиторийін таңдаңыз, Contents үшін Read and write құқығын беріңіз. Кілтті чатқа немесе кодқа қоспаңыз — сайттағы құпия өріске енгізіңіз. Сайт тек репозиторий иесінің аккаунтын қабылдайды.

Әдепкіде GitHub кілті тек беттің жадында сақталады. Иесі «Өз құпиясөзімді орнату» арқылы 10–128 таңбалы құпиясөз таңдаса, кілт AES-256-GCM шифрланған түрде ғана осы браузердің localStorage сақтауына жазылады. PBKDF2-SHA256 (310 000 итерация) және кездейсоқ тұз қолданылады; ашық кілт пен құпиясөз сақталмайды. Бетті жаңартқанда жеке құпиясөзбен қайта кіру қажет. Қалпына келтіру коды бір рет көрсетіледі; оны бөлек сақтаңыз. «Құпиясөзді ұмыттым» арқылы кодпен жаңасын орнатуға болады, бұрынғы код жарамсыз болады. Код та жоғалса, жарамды GitHub кілтімен иелік расталғаннан кейін жаңа құпиясөз орнатылады. Бұл баптау браузерге ғана тиесілі; басқа құрылғыда бөлек байланыстырылады. GitHub кілтінің мерзімі бітсе, GitHub арқылы жаңарту қажет. Кілт тек api.github.com серверіне Authorization тақырыбы арқылы жіберіледі. Оны GitHub-та қайтарып алуға немесе мерзімін шектеуге болады.

## Бірнеше файл

Бір файл 500 МиБ-қа дейін, бір жүктеу барлығы 500 МиБ-қа дейін. PDF, DOC, DOCX, PPT, PPTX, JPG, PNG, WebP, GIF қолданылады. Атауы бірдей файлдар алмастырылмайды: жаңа файлдың атауына (2), (3) сияқты белгі қосылады. Бір топ файл бір commit арқылы бірге сақталады. Қатарынан жасалған басқа өзгерістер болса, күшпен жазылмайды: тізімді жаңартып, қайталау ұсынылады.

Жаңа файлдар және жою нәтижесі басқарушыға бірден көрсетіледі. Басқа келушілерге GitHub Pages жариялауы аяқталған соң көрінеді. Оқу қоржыны мен қалған карточкалардың файлдары бөлек сақталады.

Build: node scripts/build.mjs

## Өз ұяшығын қосу

Әр бөлімдегі «＋ Ұяшық қосу» батырмасы атауын, қосымша атауын / студенттің аты-жөнін, жылын және сипаттамасын енгізетін терезені ашады. Басқаруға кіріп, «Ұяшықты сақтау» басыңыз. Жаңа ұяшық сол бөлімде сақталып, бірден көрінеді; оған бұрынғыдай бірнеше файл қосуға және әр файлды жоюға болады. Мысалы, «Студенттер жетістіктері» бөлімінде жаңа студенттің аты-жөнін және жетістігін енгізіңіз.

Ұяшықтар items.config.json ішінде custom: true белгісімен сақталады. Барлық бұрынғы ұяшықтар мен файлдар сақталады. Жариялау кезінде жаңа ұяшықтар HTML-ге де енгізіледі, сондықтан келушілерге басқаруға кіру қажет емес. Атауы мен сипаттамасы қарапайым мәтін ретінде көрсетіледі.

## Пошта және WhatsApp

Сол хаттағы растау сілтемесін бір рет басу керек. Белсендірілмеген поштаға жеткізуге кепіл берілмейді. «Пошта бағдарламасымен хат жазу» баламасы да сақталған.

Келушінің аты, поштасы және хабарламасы FormSubmit-ке жіберілетіні формада жазылған. Басқару кілті бұл қызметке берілмейді. Хабарлама қызмет тарапынан қабылданғаннан кейін ғана соған сәйкес нәтиже көрсетіледі; mailbox-қа жеткізу тексерілмейді. Қате болса, жазылған мәтін сақталады. Нақты пошта жіберу арқылы автоматты тексеріс жасалмайды.

WhatsApp батырмасы +7 776 770 73 53 нөміріне апарады. Ол байланыс бөлімінде және экранның төменгі бұрышында бар.

## Бөлімдерді жеке ашу

Мәзір бір уақытта бір бөлімді көрсетеді. Мысалы, «Мен туралы» ашылса, тәжірибе, жетістіктер, оқу материалдары және байланыс бөлімі жасырылып тұрады. Мәзірде барлық тоғыз бөлім бар, оның ішінде «Басты бет» пен «Құжаттар қоры» да бар.

Әр бөлімнің тұрақты сілтемесі сақталған: #about, #students, #learning және т.б. Браузердің артқа/алға батырмалары және тікелей сілтеме арқылы ашу жұмыс істейді. Бөлімдер арасында ауысқанда бет толық қайта жүктелмейді, сондықтан басқаруға кіру күйі және енгізіліп жатқан мәтін сақталады. Барлық ұяшықтар, құжаттар және файлды басқару функциялары өз бөлімінде қалады.

## Жиналып тұратын файлдар

Әр ұяшықтағы материалдар бастапқыда жабық. Ұяшықтың бос жерін, атауын немесе «Материалдар» жолын басқанда файлдар мен басқару батырмалары ашылады. Қайта басқанда жиналады. Жалпы құжаттар қорындағы әр файлдың фотосы мен әрекеттері де «Толығырақ» ішінде жабық тұрады. Басты беттегі портретте басқару белгісі көрсетілмейді; фотоны бассаңыз, материалдарын аша аласыз.

## 500 МБ файлдар

Бір файл және бір жүктеу 500 МиБ-қа дейін қабылданады. 16 МиБ-тан үлкен файлдар GitHub-тың бір файлға қойылатын шегінен аспайтын бөліктермен сақталады, бірақ сайтта бір файл ретінде көрсетіледі. Атауы, толық көлемі және бөлік SHA-256 хэштері .portfolio-file.json сипаттамасында сақталады. Бұрынғы шағын файлдардың пішімі өзгермейді.

Қоғамдық сайтты жинау кезінде барлық бөліктердің көлемі мен хэштері тексеріледі. Жүктеп алғанда файл қайта біріктіріліп, тұтастығы тексеріледі. File System Access API қолдайтын браузерлерде дискке бөліктеп жазылып, жады шығыны шектеледі; басқа браузерлерде Blob қолданылады. 80 МиБ-тан үлкен файлдар автоматты алдын ала қарауға жүктелмейді, оны құрылғыға жүктеп алу ұсынылады.

Ірі файлды жою сипаттамасы мен барлық бөліктерін бірге алып тастайды. GitHub Pages-тің жалпы сайт көлемі шегіне орын қалдыру үшін жарияланатын файлдар бюджеті 900 000 000 байтпен шектеледі; орын толса, нақты хабар көрсетіледі. Бұл бір файлдың 500 МиБ шегінен бөлек жалпы орын шектеуі. Файл жүктеліп жатқанда бетті жаппау керек.


## Құжаттардың қолжетімділігі

Жария сайтта тек каталог мәтіні беріледі. Құрастыру PDF, Office, фото және ірі файл бөліктерін `public/` ішіне көшірмейді; каталогта жүктеу URL-дері, blob SHA не бөліктер тізімі болмайды. Келушіге файлдар мен фотоның мазмұны, ашу/жүктеу/жою және қосу әрекеттері көрсетілмейді. Иесі GitHub арқылы расталғанда файлдар GitHub API арқылы оқылып, уақытша Blob URL түрінде ашылады. Сеанс аяқталғанда URL-дер жойылады, көрермен жабылады және каталог қайтадан тек мәтінге айналады.

**Маңызды шектеу:** бастапқы GitHub репозиторийі ашық болса, бұл өзгеріс оның Contents/Raw API-ін немесе Git тарихын жаппайды. Тек интерфейсті жасыру толық қорғаныс емес. Бұрын жарияланған көшірмелер мен алынған файлдарды кері қайтару мүмкін емес. Қойманы жеке ету әрекетін GitHub интеграциясы HTTP 403 жауабымен қабылдамады. Қорғауды аяқтау үшін иесі жеке файл қоймасын және оған иелікпен кіруді байланыстыруы қажет. Қазіргі Pages сайтын жеке репозиторийге ауыстыру хостинг жоспарына байланысты оның жұмысын тоқтатуы мүмкін; ашық мәтіндік сайт пен жеке файл қоймасын бөлек орналастыру керек.

GitHub қоймасы ашық болса, басқару панелінде аяқталмаған қорғау туралы ескерту көрінеді. Жаңа файлдарды сақтау алдындағы серверден оқылған `private` күйі `true` болмаса, жүктеу тоқтатылады; бұрынғы файлдар жойылмайды. Бұл JavaScript тексерісі GitHub қолжетімділік саясатын алмастырмайды.
